  3. Open JARVIS from the new Home Screen icon (not from Safari).

SETUP GUIDE

How it works. A Google Apps Script in your Google account reads Gmail (read-only) on a schedule, classifies with your rules, and exposes a private JSON digest. This page cannot call Gmail or Apps Script (published pages are blocked from network requests), so you import the digest here. Nothing is live: re-import to refresh. Optional: the same script pushes HIGH alerts to your own Telegram bot.

  1. Connect (sign in as juanpagil27@gmail.com; the script refuses to run on any other account): script.google.com → New project → paste the code below into Code.gs. In Project Settings enable "Show appsscript.json" and replace it with the manifest below. Services (+) → add Gmail API v1 (identifier Gmail).
  2. Config: copy the JSON from "Alert Settings" above. Project Settings → Script Properties → add CONFIG = that JSON. (Optional Telegram: TELEGRAM_TOKEN and TELEGRAM_CHAT_ID, stored only there.)
  3. Authorize: run setup once and accept the Google prompt. This also creates the periodic trigger and does a first run.
  4. Digest URL: Deploy → New deployment → Web app → Execute as Me, access Only myself. Open the URL while logged in, copy the JSON, then "Import digest" here (or save it as a .json file and use "Import file").
  5. Verify: status turns CONNECTED only after a real digest with a valid last run is imported. Check the Executions panel for errors; the digest also reports status: error.
  6. Disconnect / revoke: run removeTriggers, delete the project, then remove access at myaccount.google.com/permissions. "Clear email data" here wipes imported emails.
  7. Duplicates: the script remembers processed message ids and only looks at mail since its last run; the page also ignores repeated message ids.

Permissions requested: gmail.readonly (read mail; no send/modify/delete), script.scriptapp (create the schedule). Nothing else. Telegram is optional and OFF by default: it would need the extra scope https://www.googleapis.com/auth/script.external_request added to the manifest and sends alert text outside Google, so only enable it if you accept that. Attachments are never fetched and links are never opened by the script.

Limits: triggers run every 1–30 minutes at best (not instant), within Google's free daily quotas; up to 100 new messages per run; classification uses sender and subject only (no body), so deadlines are only detected if written as YYYY-MM-DD in the subject.
